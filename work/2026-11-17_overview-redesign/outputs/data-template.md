# 總覽頁資料範本

結構是**項目 → 需求**兩層。總覽頁的進度與本週動作都算在**需求**上；項目只負責分組。

範本分兩部分：

| | A. 需求基本資料 | B. 每週回報 |
|---|---|---|
| 誰填 | PM 與 DRI 一起建立 | DRI |
| 多久填一次 | 建立一次，有變動才改 | 每週一次，約 5 分鐘 |
| 內容 | 範圍、時程步驟與日期、DRI、關聯 | 目前步驟、範圍完成數、本週動作、需要支援 |

---

## A. 需求基本資料（建立一次）

- **範圍**（選填）：這個需求要做出哪些東西，用來算「完成幾個・共幾個」。
  例：Development Skill 要涵蓋 7 個開發階段；客戶軟體驗證有 3 條工作流。
- **時程步驟**：**我們推進這個需求**的步驟與起訖日期（不是產出物本身的內容）。每個需求可以不同。
- **關聯**（選填）：和哪個需求共用驗證或資源。總覽頁會把兩者連起來；同一件事只計一次。

```
### 項目 — 需求
- DRI：
- 範圍（選填）：共 __ 個：（列出）
- 時程步驟：
  1. ____：  ~  
  2. ____：  ~  
- 關聯（選填）：
```

## B. 每週回報（每週填）

```
### 項目 — 需求｜週次 11/17–11/23
- 目前步驟：（從時程步驟挑一個）
- 範圍完成數（有範圍才填）：完成 __ 個（本週 +__）
- 本週動作（最多 2 條、每條約 40 字，寫「做完了什麼」）：
  - 
- 需要副總支援（沒有留空；有的話寫「要什麼、何時前要」）：
```

> 數量寫成「完成 4 個・共 12 個」，不要寫「4/12」（會被看成日期）。
